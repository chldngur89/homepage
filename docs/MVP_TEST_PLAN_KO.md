# 우리팀 MVP 테스트 기획안

## 0. 검토 결론

우리팀의 MVP는 **"AI가 콘텐츠를 만들어 준다"**가 아니라, **"전담 마케터가 없는 초기 창업 대표가 짧은 승인만으로 이번 주 마케팅 실행을 시작·완료할 수 있게 한다"**로 정의하는 것이 적절합니다.

홈페이지의 `제안 → 승인 → 실행 → 반복 성장` 메시지와 에이전트의 실제 구현은 방향이 일치합니다. 다만 현재 앱에서 검증 가능한 범위는 콘텐츠·채널 실행 흐름과 승인 UX까지이며, **선제적인 주간 제안, 실제 성과 분석, 성과를 다음 제안에 자동 반영하는 기능은 아직 검증 전**입니다. 따라서 이를 한 장의 MVP로 묶어 성과를 주장하면 안 되며, 아래처럼 3개의 테스트로 나눕니다.

| MVP | 검증할 가설 | 현재 상태 |
|---|---|---|
| 1. 콘텐츠 실행 루프 | 대표가 정보 입력부터 승인 가능한 마케팅 결과물까지 스스로 완주한다 | 구현됨 · 우선 테스트 |
| 2. 승인·채널 배포 | 대표가 게시 전 통제권을 느끼며 채널별 결과물을 확정한다 | 구현됨 · 실제 계정 검증 필요 |
| 3. 주간 제안·반복 성장 | 먼저 제안받고 다음 주에도 다시 사용하는 운영 습관이 생긴다 | 제품 가설 · 컨시어지 테스트 권장 |

## Sheet 1. MVP 테스트 — 콘텐츠 실행 루프

### 1) 핵심 가치와 핵심 기능

| 구분 | 내용 |
|---|---|
| 핵심 가치 | 전담 마케터가 없는 대표가 마케팅 업무를 외주 맡기거나 여러 도구를 오가며 만들지 않고, 한 흐름 안에서 실행 가능한 콘텐츠 캠페인을 준비한다. |
| 핵심 기능 | 채팅/상품 폼으로 제품·가격·브랜드·콘셉트를 입력하고, 사진·스타일·주기를 선택하면 시나리오와 이미지, 채널별 콘텐츠 초안을 생성한다. |
| 타깃 고객 | 전담 마케터가 없는 국내 1~10인 초기 창업팀의 대표 또는 실무자. |
| 사용자 완료 행동 | 자신의 상품으로 콘텐츠 결과물을 확인하고, 인스타그램 또는 네이버 채널을 선택해 캠페인을 저장한다. |

### 2) MVP 테스트

| 항목 | 설계 |
|---|---|
| 검증 가설 | 타깃 사용자는 설명 도움 없이 제품 정보 입력부터 채널 선택·캠페인 저장까지 완료할 수 있으며, 결과물을 "이번 주에 바로 쓸 수 있는 마케팅 작업"으로 인식한다. |
| 테스트 방식 | 5~8명의 타깃 대표에게 실제 상품 1개를 가져오게 한 뒤, 앱에서 1개 캠페인을 만드는 사용성 테스트를 진행한다. 진행자는 막힌 지점만 기록하고 먼저 안내하지 않는다. |
| 테스트 시나리오 | ① 상품/가격/브랜드/콘셉트 입력 ② 사진 첨부 또는 AI 이미지 선택 ③ 스타일·발행 주기 선택 ④ 시나리오·이미지 확인 ⑤ 채널 선택 ⑥ 캠페인 저장. |
| 수집 데이터 | 완료 여부, 완료 시간, 도움 요청 횟수, 이탈 단계, 결과물 수정 요청, "다음 주에도 쓸 의향"(5점), 인터뷰 발화. |
| 성공 기준 | 70% 이상이 도움 없이 캠페인 저장까지 완료, 중앙 완료 시간 15분 이내, 5점 척도 사용 의향 평균 4점 이상, 과반이 결과물을 실제 게시 후보로 평가. |
| 실패 시 판단 | 입력 항목이 어렵다면 상단 폼의 용어·순서를 수정한다. 시나리오/이미지 만족도가 낮다면 생성 품질과 재생성 선택지를 개선한다. 채널 선택에서 멈추면 채널별 기대 결과를 더 명확히 보여 준다. |

### 3) 테스트 개요

| 항목 | 내용 |
|---|---|
| 기간 | 1주차: 5~8명 인터뷰·관찰 / 2주차: 이슈 수정 후 3명 재검증 |
| 리크루팅 | 최근 3개월 내 직접 SNS·블로그·스마트스토어 마케팅을 해 본 1~10인 팀 대표. |
| 사전 준비 | 테스트 계정, 데모 상품 또는 참가자 실제 상품, 화면 녹화 동의, 관찰 기록지. |
| 종료 질문 | "기존 방식과 비교해 줄어든 일이 무엇인가?" "결과물 중 실제 게시하지 못할 이유는 무엇인가?" "다음 주에 다시 열 이유가 있는가?" |

## Sheet 2. MVP 테스트 — 승인·채널 배포

### 1) 핵심 가치와 핵심 기능

| 구분 | 내용 |
|---|---|
| 핵심 가치 | AI가 실행하더라도 대표가 게시 전 방향과 문구를 통제할 수 있어 안심하고 실행을 맡긴다. |
| 핵심 기능 | "이 카드로 올릴까요?" 승인, 인스타 캡션 및 네이버 제목·본문 미리보기·편집·확정, 업로드 상태 확인, 실패 시 재시도, 알림함. |
| 현재 제약 | 인스타그램 실계정 게시 경로는 E2E 검증이 필요하다. 네이버 블로그는 자동 게시하지 않으며 `pending_manual` 상태와 HTML 내보내기/복붙 안내가 필요하다. |

### 2) MVP 테스트

| 항목 | 설계 |
|---|---|
| 검증 가설 | 사용자는 AI가 만든 결과물을 그대로 게시하는 것이 아니라, 검토·수정·확정할 수 있다는 점 때문에 게시 실행 의향을 가진다. |
| 테스트 방식 | MVP 1 완료자 중 5명을 대상으로 생성된 콘텐츠를 실제 자신의 채널에 올리는 과정을 관찰한다. 인스타 실계정 3명 이상, 네이버 블로그 2명 이상을 목표로 한다. |
| 테스트 시나리오 | ① "지금 바로 업로드" 선택 ② 승인 카드에서 올리기/나중에 선택 ③ 채널별 카피 수정·확정 ④ 인스타 게시 또는 네이버 수동 게시 안내 수행 ⑤ 실패 발생 시 재시도·알림 확인. |
| 수집 데이터 | 승인 전 수정 여부·수정 항목, 실제 게시/수동대기 비율, 게시 완료까지 시간, 실패 원인 이해도, 통제감·신뢰도(5점), 재시도 성공 여부. |
| 성공 기준 | 80% 이상이 승인·카피 확정을 완료, 60% 이상이 테스트 중 실제 게시 또는 수동 게시 준비 완료, 통제감 평균 4점 이상, 실패 발생자가 재시도 방법을 스스로 찾음. |
| 실패 시 판단 | 대표가 자동 게시를 불안해하면 승인 카드에 채널·이미지·문구·예상 상태를 더 명확히 표시한다. 네이버 수동 전환에서 멈추면 HTML 내보내기와 복붙 안내를 한 화면에 제공한다. |

### 3) 테스트 원칙

- "자동 게시 가능"을 성공 기준으로 삼지 않습니다. 실제로는 대표의 승인과 채널별 제약을 투명하게 다루는지가 핵심입니다.
- 인스타그램 실게시와 네이버 수동 게시를 한 성공 지표로 합치지 않습니다. 네이버는 현재 의도적으로 수동 경로입니다.
- 실패 재시도, 알림 배지, 대시보드 상태 확인은 보조 기능이지만 신뢰 형성에 중요하므로 관찰 항목에 포함합니다.

## Sheet 3. MVP 테스트 — 주간 제안·반복 성장

### 1) 핵심 가치와 핵심 기능

| 구분 | 내용 |
|---|---|
| 핵심 가치 | 대표가 "이번 주에 무엇을 해야 하지?"를 혼자 결정하지 않아도, 사업 맥락에 맞는 다음 행동을 먼저 받아보고 승인할 수 있다. |
| 핵심 기능(목표) | 지난주 결과와 제품·채널 맥락을 바탕으로 주간 성장 과제를 제안하고, 대표의 승인 후 콘텐츠·캠페인 실행으로 연결하며, 결과를 다음 제안에 반영한다. |
| 현재 상태 | 홈페이지의 핵심 약속이지만, 앱의 자동 스케줄러·실채널 애널리틱스·학습 루프는 보류 상태다. 현재 대시보드 지표는 mock/미리보기 수준이므로 제품 성과로 주장하지 않는다. |

### 2) MVP 테스트

| 항목 | 설계 |
|---|---|
| 검증 가설 | 타깃 대표는 매주 새 도구를 열어 질문하기보다, 자신의 맥락을 반영한 "이번 주 제안"을 먼저 받고 승인·수정하는 방식을 더 유용하게 느낀다. |
| 테스트 방식 | 4주간 5개 팀을 대상으로 **컨시어지 MVP**를 운영한다. 매주 운영자가 앱/메시지로 3개의 우선순위 제안을 보내고, 대표의 승인·수정 의견을 받아 현재 앱의 콘텐츠 실행 루프로 연결한다. |
| 비교 기준 | 참가자의 기존 방식(직접 기획, ChatGPT 질문, 외주 요청)과 비교해 의사결정·준비 시간, 제안 채택률, 다음 주 재참여를 기록한다. |
| 수집 데이터 | 주간 제안 열람률, 승인/수정/거절 비율, 제안당 실행 전환율, 주간 재방문율, 대표가 절감했다고 느낀 시간, 실제 채널 반응(가능한 경우). |
| 성공 기준 | 4주 중 3주 이상 제안을 열람한 팀 60% 이상, 제안의 실행 전환율 40% 이상, 4주차에도 자발적으로 다음 제안을 요청한 팀 3곳 이상. |
| 실패 시 판단 | 제안이 거절되면 맥락 수집 방식과 우선순위를 수정한다. 제안은 읽지만 실행하지 않으면 콘텐츠 제작·채널 배포의 마찰을 별도로 개선한다. 재방문이 낮으면 주간 제안의 시간·형식·전달 채널을 바꾼다. |

### 3) 반드시 지킬 표현

- 현재: "콘텐츠 생성·승인·채널별 카피 확정·업로드 상태 관리 흐름을 구현했다."
- 검증 중: "주간 제안을 통해 반복 사용이 생기는지 컨시어지 MVP로 검증한다."
- 아직 말하면 안 되는 표현: "성과를 자동 분석해 다음 주 전략을 최적화한다", "채널 자동 게시가 완료됐다", "마케팅 성과가 개선됐다".

## 공통 인터뷰 기록지

| 질문 | 기록할 내용 |
|---|---|
| 평소에는 이번 주 마케팅 할 일을 어떻게 정하나요? | 현재 대안·소요 시간·외주 여부 |
| 어느 순간에 다음 행동을 알 수 없었나요? | 문제의 강도와 발생 맥락 |
| 결과물 중 실제로 쓸 수 있는 것과 없는 것은 무엇인가요? | 품질·브랜드 톤·수정 사유 |
| 승인 과정에서 불안하거나 안심된 점은 무엇인가요? | 통제감·신뢰의 근거 |
| 다음 주에도 우리팀을 열 이유가 있나요? | 재방문 동기·유료 전환 단서 |
| 이 서비스가 없으면 무엇으로 돌아가나요? | 진짜 경쟁 대안 |

## 홈페이지와 MVP 문서의 정합성 권고

1. 홈페이지의 메인 약속인 `제안 → 승인 → 실행 → 반복 성장`은 유지하되, 파일럿에서는 "반복 성장"을 **검증할 가설**로 표기합니다.
2. "이번 주 할 일을 먼저 제안"한다는 문구는 자동화가 출시되기 전에는 컨시어지 운영 또는 파일럿 제공 범위를 함께 명시합니다.
3. 네이버는 자동 게시가 아니라 수동 게시 지원이라는 현재 제약을 온보딩·판매 문구에도 투명하게 적습니다.
4. 가격 페이지의 "무제한 사용", 성공 기반 수익 쉐어 등은 실제 운영 정책·결제·계약 조건이 확정되기 전에는 MVP 검증 문서의 실험 조건과 분리합니다.
