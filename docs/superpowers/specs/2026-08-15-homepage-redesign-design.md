## 2. 목표 / 비목표

**목표**

- 사이트 전체를 새 디자인의 라이트 에디토리얼 언어로 전환한다.
- 색상 결정을 토큰 한 곳으로 모아, 이후 색을 바꿀 때 페이지를 뒤지지 않게 한다.
- 제품 화면을 실제로 보여준다.
- 핵심 7개 페이지에 영문판(`/en/`)을 붙인다.
- 이미지는 **파일 교체만으로** 바뀌는 구조로 만든다.

**비목표**

- 브랜드 마크(심볼) 신규 제작. 새 디자인은 워드마크만으로 성립하므로 이번 범위에서 제외한다.
- 제품 앱 자체의 UI 변경.
- 데모 시뮬레이션의 동작 로직 변경. 외형만 전환한다.
- 개인정보처리방침·이용약관의 영문화. 한국어본을 정본으로 유지한다.

## 4. 디자인 시스템

### 4.1 토큰

`src/styles/theme.css`에 브랜드 토큰을 정의하고 Tailwind v4 `@theme`으로 유틸리티화한다.

```
--ground   #F7F7F4   페이지 배경 (웜 오프화이트)
--surface  #FFFFFF   카드·표 배경
--muted    #F0F0EC   섹션 교대 배경
--ink      #161616   본문·제목
--ink-2    #5E5E59   보조 본문
--ink-3    #8B8B85   캡션·라벨
--line     #DEDED8   주 구분선
--line-2   #E4E4DF   카드 아웃라인
--accent   #4F6B5B   포인트 (세이지)
--invert   #111111   다크 CTA 섹션 배경
```

기존 shadcn 토큰(`--background`, `--foreground`, `--border` 등)은 **제거하지 않고 위 토큰 위에 다시 매핑**한다.
`src/app/components/ui/*`의 radix 기반 컴포넌트가 계속 동작해야 하기 때문이다.

전환이 끝난 페이지에서는 `slate-*`, `cyan-*`, `indigo-*`, `pink-*` 직접 사용을 금지한다.

### 4.2 타이포그래피

- 서체: Pretendard Variable, jsDelivr **동적 서브셋** CDN.
  한글 가변 폰트 전체는 1MB를 넘는데 동적 서브셋은 사용된 글자만 로드하므로 자체 호스팅보다 유리하다.
  대신 서드파티 의존이 생기므로 `index.html`에 `preconnect`를 추가하고, CDN 장애 시를 대비해
  `system-ui, -apple-system`으로 폴백한다.
- 본문 `word-break: keep-all` — 한글 단어가 어절 단위로 끊긴다. 새 디자인의 전제다.
- 제목 `letter-spacing: -.03em ~ -.035em`, `line-height: 1.14~1.3`.
- 라벨(`01 누구를 위한가`)은 `letter-spacing: .12em`, `12.5px`, `--ink-3`.

### 4.3 레이아웃

- 콘텐츠 최대폭 `1180px`, 좌우 패딩 `clamp(20px, 4vw, 40px)`.
- 섹션 세로 패딩 `clamp(72px, 8vw, 112px)`, 섹션 사이 `1px solid var(--line)`.
- 비대칭 스플릿 그리드(`55fr 45fr`, `44fr 56fr`, `38fr 62fr` 등)가 이 디자인의 리듬이다.
  `1080px` 이하에서 단일 컬럼으로 접힌다.
- 카드는 `box-shadow: 0 0 0 1px var(--line-2)` 헤어라인. `border-radius`는 14px 이하로 억제.

### 4.4 모션

- 진입 애니메이션은 `rise`(8px 상승 + 페이드, 0.55s) 하나로 통일한다.
- `prefers-reduced-motion: reduce`에서 전면 비활성화한다.
- 현재 `motion` 라이브러리를 페이지마다 개별 설정으로 쓰고 있는데, 이를 CSS 애니메이션 한 종류로
  줄인다. 번들도 줄고 스크롤 리듬도 일정해진다.

## 5. 아키텍처

### 5.1 콘텐츠 / i18n

```
src/content/
  locales.ts          Locale 타입, 기본 로케일, 지원 목록
  ko/
    common.ts         브랜드·네비게이션·푸터·CTA
    home.ts
    solution.ts       ... 페이지별
  en/
    common.ts
    home.ts           ... 영문 7개만
src/app/i18n/
  LocaleContext.tsx   라우트에서 로케일을 읽어 사전을 제공
  useCopy.ts          useCopy('home') → 타입이 붙은 사전
  localePath.ts       '/pricing' + 'en' → '/en/pricing'
```

- 한국어 사전이 타입의 원본이다. 영문 사전은 같은 타입을 구현해야 하므로,
  **번역 누락은 타입 에러로 잡힌다.**
- 영문판이 없는 페이지(`/demo`, `/apps`, `/privacy`, `/terms`)로 가는 링크는
  영문 화면에서도 한국어 경로를 가리키고, 링크에 `lang="ko"`를 표기한다.
- 기존 `site.json` / `apps.json` / `ir.ts`는 `ko/` 사전으로 흡수한다.

### 5.2 라우팅 / prerender

- `/` 트리(11개) + `/en` 트리(7개). 라우트 정의는 로케일을 인자로 받는 하나의 팩토리에서 생성한다.
- `prerenderRoutes` = 18개.
- `ssg/seo.ts`는 `${locale}:${path}` 키로 재구성하고 다음을 출력한다:
  - 로케일별 `title` / `description`
  - `<html lang>` (`ko` / `en`)
  - `canonical`
  - `hreflang` alternate (`ko`, `en`, `x-default`=`ko`)
  - `og:locale` (`ko_KR` / `en_US`)
- `sitemap.xml`에 18개 경로를 모두 포함한다.

### 5.3 이미지 슬롯

```
src/app/components/ImageSlot.tsx
src/app/config/images.ts        슬롯 레지스트리 (경로·비율·설명·sample 여부)
public/img/<slot>.png           샘플 이미지
```

- `ImageSlot`은 `ratio`를 CSS `aspect-ratio`로 고정한다. **진짜 사진으로 바꿔도 레이아웃이 흔들리지 않는다.**
- 교체 절차: `public/img/<슬롯>.png`를 같은 이름으로 덮어쓴다. 코드 변경 없음.
- 샘플 이미지의 정체: 사진이 아니라 **브랜드 팔레트 기반의 무채색 질감 구성**이다.
  HTML로 그린 뒤 지정 비율 그대로 PNG로 내보낸다. 레이아웃이 완성돼 보이게 하는 것이 목적이며,
  최종 아트가 아니다. 그라데이션 블롭·추상 3D 같은 흔한 생성형 시각 요소는 쓰지 않는다 —
  그 자체가 "AI로 만든 사이트" 신호로 읽히기 때문이다.
- 레지스트리의 `sample: true`를 `scripts/verify-assets.mjs`가 읽어,
  **빌드할 때마다 아직 교체되지 않은 샘플 목록을 경고로 출력한다.** 잊고 배포하는 것을 막는다.

| 슬롯 | 비율 | 채울 내용 |
|------|------|----------|
| `persona` | 5:4 | 대표의 업무 환경 (책상·노트·화면) |
| `voice-1` | 1:1 | 손 또는 화면 일부 크롭 |
| `voice-2` | 1:1 | 책상 또는 노트 일부 크롭 |
| `footer-wide` | 3.16:1 | 작은 사무실 / 업무 중인 손 |

후기 아바타(`voice-1`, `voice-2`)는 **사람 얼굴을 쓰지 않는다.** 두 인용문은 파일럿 인터뷰를
정리한 문장이지 축어 인용이 아니며, 얼굴 사진을 붙이면 실제 고객 후기로 읽힌다.
디자인 원본의 주석("실제 인터뷰 문장으로 교체 예정")과 같은 취지로, 손·책상 크롭을 유지하고
출처 문구를 본문에 남긴다.

### 5.4 제품 목업 컴포넌트

```
src/app/components/mockups/
  ProposalCard.tsx      히어로 — 이번 주 제안 화면 (4:3)
  ChatThread.tsx        03 섹션 — 주간 제안 대화 (16:11)
  ResultDashboard.tsx   05 섹션 — 주간 결과 리포트 (16:9)
```

- 순수 표현 컴포넌트. 표시할 내용은 콘텐츠 사전에서 받아 **로케일에 따라 화면 속 문구도 바뀐다.**
- 디자인 토큰만 사용한다. 제품 화면이 사이트와 같은 팔레트로 보이는 것이 이 방식의 이점이다.
- 화면 안 숫자는 예시임을 디자인 원본대로 각주로 명시한다
  ("화면에 표시된 숫자는 설명을 위한 예시입니다").

### 5.5 브랜드 자산

- 헤더·푸터 로고: 이미지 제거, `우리팀` + `WOORITEAM` 워드마크 조합으로 대체.
- `favicon.png` / `apple-touch-icon.png`: 새 팔레트 기준 워드마크 파비콘으로 교체.
  현재 파일은 다크 배경 네온 'C'라 라이트 사이트와 정면으로 충돌한다.
  `우리` 두 글자 또는 `W` 모노그램을 `--ground` 위 `--ink`로 놓은 형태로 생성한다.
- `index.html`의 `theme-color`를 `#F7F7F4`로 변경.
- OG 이미지: `/flow/flow-form.png` 사용을 중단하고, 새 팔레트의 타이포그래피 OG 카드(1200×630)를
  생성해 `public/og/` 에 둔다. 로케일별로 한 장씩.

## 6. 페이지별 전환 계획

기반 → 공통 → 홈 → 나머지 순으로, **각 단계가 끝날 때마다 사이트가 동작하는 상태**를 유지한다.

| 단계 | 대상 | 내용 |
|------|------|------|
| 0 | 기반 | 토큰, 폰트, `ImageSlot`, i18n 스캐폴드, 라우트·SEO 구조 |
| 1 | `Layout.tsx` | 헤더·푸터 전환. 이 시점에 사이트 전체 인상이 바뀐다 |
| 2 | `Home.tsx` | 7개 섹션 + 목업 3종 + 이미지 슬롯 4종. 한/영 |
| 3 | `Solution` `Pricing` `Technology` | 전환 유입이 큰 순서. 한/영 |
| 4 | `About` `Contact` `IR` | 한/영 |
| 5 | `Demo` `Apps` `Privacy` `Terms` | 한국어만 |
| 6 | 자산·SEO | 파비콘, OG 카드, `theme-color`, sitemap, hreflang |
| 7 | 검증 | 아래 7절 |

`Demo.tsx`는 시뮬레이션 동작이 있으므로 외형만 바꾸고 로직은 그대로 둔다.
`IR.tsx`는 777줄로 가장 크고 `recharts` 차트를 포함한다. 차트 색상도 토큰으로 옮긴다.

## 7. 검증

README에 이미 정립된 절차를 그대로 따르고, 다국어 항목을 추가한다.

1. `npm run build` — `verify-assets`가 통과하고, 남은 샘플 이미지 경고 목록을 확인한다.
2. `npm run preview` 후 `curl`로 **초기 HTML에 본문이 있는지** 확인한다.
   - `curl -s http://127.0.0.1:4173/ | rg "첫 번째 팀|제안 → 승인 → 실행 → 반복 성장"`
   - `curl -s http://127.0.0.1:4173/en/ | rg "first team"`
   - 한국어 페이지 HTML에 영문 카피가 섞여 있지 않은지 확인한다.
3. `hreflang`·`canonical`이 로케일별로 올바른지 확인한다.
4. DevTools에서 JavaScript를 끄고 본문이 보이는지 확인한다.
5. 모바일 375px 폭에서 각 페이지를 확인한다 — 스플릿 그리드가 접히는지, 가로 스크롤이 없는지.
6. `prefers-reduced-motion`을 켠 상태에서 애니메이션이 꺼지는지 확인한다.
7. 대비: 본문 `--ink-2`(#5E5E59) on `--ground`(#F7F7F4)와 액센트 `--accent`(#4F6B5B)가
   WCAG AA(4.5:1)를 넘는지 측정한다. 넘지 못하면 토큰을 조정한다.
